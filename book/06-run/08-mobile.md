## Мобильные приложения

С мобильными приложениями всё то же самое — агент должен уметь сам собрать приложение, запустить его на симуляторе iOS или эмуляторе Android, пройти по экранам, наделать скриншотов и сравнить, как экран выглядит сейчас и как должен выглядеть. Последовательность команд для сборки у тебя может быть хитрая, так что пусть у тебя будет скрипт, который собирает приложение, и ещё один — который выкладывает сборку для тестировщиков в TestFlight или во внутреннее тестирование Google Play. Оба скрипта агент напишет сам по такому же промпту, как скрипт сборки в начале главы.

С iOS сейчас проще всего, потому что, начиная с Xcode 26.3, Apple сама пускает внешних агентов к инструментам Xcode, а в Xcode 27 агенты научились сами запускать симуляторы, ставить на них приложения, нажимать на экран и делать скриншоты. Есть и MobileBuildMCP — MCP-сервер от Sentry, сервиса мониторинга ошибок. Он тоже собирает приложение, запускает его на симуляторе, нажимает, листает, делает скриншоты и пишет видео. Раньше он назывался XcodeBuildMCP, так что в статьях постарше ищи его под этим именем.

::: say cat
TestFlight — сервис Apple, через который тестировщики ставят сборку приложения и присылают отзывы ещё до публикации — [developer.apple.com](https://developer.apple.com/testflight/), а во внутреннее тестирование Google Play можно пригласить до 100 тестировщиков — [support.google.com](https://support.google.com/googleplay/android-developer/answer/9845334)
:::

::: say cat
Чтобы пустить агента к Xcode, в настройках Intelligence включают «Allow external agents to use Xcode tools» — [developer.apple.com](https://developer.apple.com/documentation/xcode/giving-external-agents-access-to-xcode)
:::

Для Android есть официальный Android CLI, который Google делал прежде всего для агентов. А открытый MCP-сервер mobile-mcp от проекта Mobile Next работает сразу и с iOS, и с Android, причём и с симуляторами, и с настоящими устройствами.

```terminal
# iOS: подключить к Claude Code инструменты Xcode
$ claude mcp add --transport stdio xcode -- xcrun mcpbridge

# Android: запустить эмулятор, поставить приложение, снять экран и его разметку
$ android emulator start <имя устройства>
$ android run --apks=<путь к apk>
$ android screen capture --output=screen.png
$ android layout
```

::: note sparrow
А если агент сегодня прошёл по экранам руками, завтра ему что, проходить их заново?
:::

Чтобы путь, который агент один раз прошёл по приложению, не пропадал вместе с сессией, его можно сохранить тестом Maestro. Maestro — это инструмент для UI-тестов мобильных приложений, в котором тест пишется простым файлом на YAML и один и тот же файл работает и на iOS, и на Android. Через MCP-сервер Maestro агент сначала проходит по приложению, а потом сохраняет пройденный путь тестом в репозиторий — так же, как Playwright-агенты делают это для веба. Дальше этот тест можно запускать в CI при каждом изменении. А чтобы тест заодно сравнивал экран с эталонным скриншотом, в него добавляют команду `assertScreenshot`.

```terminal
$ claude mcp add maestro -- maestro mcp
```

А проверить, что всё это работает, можно так же, как с вебом. Открой свежую сессию и попроси агента собрать приложение, поставить его на симулятор и пройти основной сценарий от начала до конца, записав видео, — и если он справится сам, мобильное приложение тоже можно отдавать ему целиком.
